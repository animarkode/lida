# Lida MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Локальний Android-застосунок, у якому можна швидко записати, де зупинився у фільмі чи серіалі: список, додавання/редагування, «+1 епізод», soft delete.

**Architecture:** MVVM з одним `StateFlow<UiState>` на екран. Дані в Room за інтерфейсом `WatchRepository` (реалізація `LocalWatchRepository`), DI вручну через `AppContainer`. Пакети за фічами (`data/`, `feature/list`, `feature/edit`, `ui/`).

**Tech Stack:** Kotlin, Jetpack Compose (Material 3), Room + KSP, Navigation Compose, Lifecycle ViewModel, JUnit4, kotlinx-coroutines-test, Compose UI Test.

**Spec:** Claude Doc «План: Android-застосунок для фільмів і серіалів» — https://claude.ai/artifact/6PmGsWMP9KZuFLifSJNcXP

## Global Constraints

- Пакет: `com.animarkode.lida` (у spec `com/alex/watchtracker` — замінюємо на реальний namespace проєкту).
- `minSdk = 29`, `compileSdk = 37`, `targetSdk = 37`, AGP 9.5.1, Kotlin 2.2.10, Gradle 9.6.0 — як уже в проєкті.
- MVP працює локально, без сервера й без мережевих дозволів.
- `id` записів — `UUID.randomUUID().toString()`; видалення тільки soft delete (`deleted = true`), рядки фізично не видаляються.
- `WatchEvent` і поле `status` закладаються вже в MVP (порада зі spec: «історія, яку не записав, потім не відновиться»), щоб дашборд не потребував міграції.
- «+1 епізод» оновлює `WatchItem` і пише `WatchEvent` в одній транзакції.
- ViewModel не знає про Compose і `Context`; екрани тільки малюють стан і викликають методи ViewModel.
- Hilt, domain-шар, use cases — не додавати.
- `android:allowBackup="true"` лишається (Auto Backup у Google Drive).
- Дашборд, TMDB, експорт/імпорт, синхронізація — **поза цим планом** (окремі плани після MVP).

## Review Focus

1. **Серіал без епізоду/сезону** (`episode == null`) і «+1 епізод» → епізод стає `1`, сезон `1`, без крешу. Тест: Task 3.
2. **Неправильний таймкод** («90:00», «abc», «1:2:3») → помилка під полем, запис не зберігається; порожній таймкод дозволений. Тест: Task 5.
3. **Порожня або з пробілів назва** → помилка, не зберігається; назва зберігається обрізаною (`trim`). Тест: Task 5.
4. **Видалений запис** не з'являється в списку і не відкривається на редагування; повторне «+1» по видаленому — no-op. Тест: Task 2, Task 3.
5. **Зміна типу SERIES → MOVIE** при редагуванні → `season`/`episode` зберігаються як `null`. Тест: Task 5.
